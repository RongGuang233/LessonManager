# 手动发布学费余额

课时簿仍在 Mac 本地记课。点击页面右上角“发布学费余额”，只上传学生 ID、姓名、状态、余额及核对状态的加密摘要。发布不修改课程、缴费、银行余额，也不自动定时更新。手机在订阅簿中手动“刷新学费余额”。

中转复用服务器现有 OpenResty 的 DAV 上传和静态文件下载，不新增 Python 服务、容器或监听端口；服务器只保存最新加密文件。首次使用先准备经本人确认配置的 HTTPS 中转地址、上传令牌和下载令牌。在设置 → 订阅簿学费同步 → 连接设置填入地址和上传令牌，生成共享加密密钥并保存。凭据保存在 macOS 钥匙串；普通 JSON / SQLite 备份不包含它们。保存设置不访问服务器。实际“发布”才会联网；未获服务器操作授权前不要点击。

手机填写相同地址、共享加密密钥及独立下载令牌。稍后需要重新配对时，在 Mac 点击“查看手机配对密钥”。共享密钥不发送到服务器，也不要写入服务环境文件。更换共享密钥后手机需重新配对。

## 可选运行时依赖

普通记课仍只用标准库；加密发布需要 `requirements-sync.txt`。在项目目录执行：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-sync.txt
```

双击启动脚本优先使用项目 `.venv/bin/python`。不要对现有账本执行测试或导入示例。

依赖采用 PyCA `cryptography>=46,<51`，范围允许维护版本更新而不强制锁定一次构建。2026-10-17 本地 `.venv` 安装并验证 AESGCM 导入的版本为 50.0.2；该安装包 METADATA 的 `Requires-Python` 为 `>=3.9, !=3.9.0, !=3.9.1`，符合课时簿 Python 3.10+ 的要求。同日对 Python 3.10 / macOS ARM64 执行 pip dry-run，成功解析到 `cryptography-50.0.2-cp39-abi3-macosx_11_0_arm64.whl`；当前较新解释器选择 `cp311-abi3` wheel 不代表该版本最低要求 Python 3.11。此为依赖解析验证，未在 Python 3.10 解释器下重跑应用测试。许可证为 Apache-2.0 或 BSD-3-Clause；选用 BSD-3-Clause。核对来源：[PyPI](https://pypi.org/project/cryptography/)、[安装说明](https://cryptography.io/en/latest/installation/)、[许可证](https://github.com/pyca/cryptography/blob/main/LICENSE)。

## 统计与失败行为

余额直接取课时簿已有结算后的当前余额。未核实余额、或有尚未包含在历史结算中的已完成课程费用待核对时，摘要 `verified=false`；历史结算已覆盖的缺日期旧课不再次影响当前余额。暂停和归档学生也发送，由手机选择导入。

上传使用 AES-256-GCM，本机随机生成 12 字节 nonce、固定 AAD `RenewBoard tuition v1`，服务器不持有解密密钥。20 秒请求超时，不跟随重定向，不自动重试。OpenResty 首次写入返回 201，覆盖已有文件返回 204，两者都确认成功；其他状态不更新本机上次成功发布时间。网络中断可能已上传但未收到回执，再手动发布即可；手机使用发布时间判断新旧。重复点击同一次发布不会并发发送。配置应让上传先写临时文件，完整接收后再替换目标；认证失败、超限或请求体未传完整时保留原文件。响应丢失也可能发生在替换已完成之后，客户端不能据此断定服务器仍是旧文件。

发布所用的连接记录和上次发布时间位于同一钥匙串项，和业务备份分离。首次使用会请求 macOS 钥匙串访问权限；取消时显示错误，不退回明文保存。

本地测试使用临时账本和内存凭据 adapter，无需读取或写入真实钥匙串，不会接触业务数据库。发布客户端的真实回环 HTTP 测试覆盖 201/204 成功、401/403/413/500/200 失败及 302 不跟随重定向；OpenResty 的实际失败保旧验证和部署配置见订阅簿项目同步文档。
